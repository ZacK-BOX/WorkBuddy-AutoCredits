## 二、包装器做了什么

`scripts/run_daily.py` 只做四件事，不碰业务逻辑：

1. 解析解释器优先级：`WBDAILY_PYTHON` → `sys.executable` → Anaconda → 托管 3.13.12。
2. **原样透传环境**（`env = os.environ.copy()`），并在日志首部打印 `http_proxy/https_proxy/no_proxy` 实际值用于核对——这是「不清空代理」的机器化证明。
3. `subprocess.run(..., capture_output=True)` **同步等待**，不设截断超时；原样回放 stdout/stderr，退出码原样 return。
4. 正则抽取三条汇报要素：
   - `🏁` 结尾进度行
   - `✅签到` 行
   - 全部含 `⚠️` 的行 + 风险关键词命中（`登录态已失效` / `未找到登录凭据` / `网络不可达` / `Traceback` / `NoAccessToken` / `ConnectionError`）

抽取不到就打印「（未找到 … 行）」，**不回填任何猜测值**。

## 四、分诊决策树

```
退出码 == 0 且 stderr 空 且 未命中风险关键词
  └─> 正常。附 🏁 行 + ✅签到 行；剩余 accepted 项一句话带过。
        └─ 仍出现「⚠️新任务需手动/未覆盖新任务」→ 单独列，标为需人工，不算故障。

命中「登录态已失效」或 HTTP 401
  └─ 先查是不是 $wbEncrypted 加密信封（见下）。是 → 不报错，主脚本照跑。

signin.py 输出 SKIPPED_ENCRYPTED_CRED（退出码 0）
  └─ 预期行为。不提示重登，不影响主脚本。

退出码 != 0 / stderr 有 Traceback
  └─ 判因：主脚本 token 续期失败（检查 wb_refresh_tokens.json 是否可读）、
          网络不可达、脚本自身异常。把最后 5 行原始日志贴给用户。

⚠️未覆盖新任务
  └─ 官方新增了脚本不认识的任务 → 记录任务 code 与标题，建议更新脚本任务模板。
```

### 加密凭据误报（高频坑）

新版桌面端把 `auth.accessToken`（位于
`%LOCALAPPDATA%\CodeBuddyExtension\Data\Public\auth\workbuddy-desktop.info`）
从明文 JWT 改成 AES-GCM 信封 `{"$wbEncrypted":1,"envelope":"…"}`。
`signin.py` 直接把 dict 拼进 `Authorization: Bearer`，于是 401，并输出误导性文案
「登录态已失效（HTTP 401），请重新登录」——**登录态其实有效**，重试/重登都解决不了。

判别方法：读凭据文件，看 `auth.accessToken` 是不是 `dict`。
- 是 dict → 加密版，属预期；
- 是 str（旧版明文 JWT）→ 可直接用。

处理：忽略该信号，主脚本走 `wb_refresh_tokens.json` 链路可正常工作。

## 五、跨轮对比口径

记录这些字段便于发现突变（每次执行后写入自动化 memory）：

- `完成X/Y 等级N`
- `剩余` 任务列表（只列新增/消失的项，说明任务清单变动）
- `连签N天 / 能量N / 累签N天`
- 积分主套餐余额（注意它会因消耗而下降，不是异常）
- 旅行状态（旅行中剩余分钟 / 今日次数已用尽）

**已知非异常变动**：任务总数分母会随官方清单调整（2026-09-30 轮 17/19，2026-10-01 轮 16/18）。

## 六、汇报模板

```
✅ 定时任务已正常执行完成，无需您处理任何事项。

执行结果摘要：
- 进度：`<🏁 行原文>`
- 签到：`<✅签到 行原文>`
- 异常：无（退出码 0、stderr 空、无登录失效/无凭据/网络不可达/脚本报错）
```
